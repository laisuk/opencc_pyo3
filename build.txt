opencc-pyo3 — Build and Installation Guide
==========================================

Requirements
------------
- Python 3.8 or newer.
- A virtual environment is recommended for installation and development.
- Building from source requires a Rust toolchain and a compatible Python build environment.
- Direct maturin commands require maturin (for example: python -m pip install maturin).
- Run source-build commands from the repository root.

1. Install a prebuilt wheel from PyPI (recommended)
---------------------------------------------------
python -m pip install opencc-pyo3

PyPI releases contain platform-specific wheels. No Rust compiler is required
when a compatible prebuilt wheel is available. Each wheel bundles its matching
PDFium native library.

2. Install directly from GitHub source
--------------------------------------
# Git checkout (Git must be installed):
python -m pip install "git+https://github.com/laisuk/opencc_pyo3.git@master"

# Or GitHub ZIP archive (Git not required):
python -m pip install "https://github.com/laisuk/opencc_pyo3/archive/refs/heads/master.zip"

The custom PEP 517 build backend synchronizes the host platform's PDFium native
library automatically, then delegates wheel building to maturin. Rust is
required. No separate PDFium synchronization command is needed for these pip
source installs.

3. Clone and build locally with maturin
---------------------------------------
git clone https://github.com/laisuk/opencc_pyo3.git
cd opencc_pyo3

# Create and activate a virtual environment (recommended):
python -m venv .venv

# Windows PowerShell:
# .\.venv\Scripts\Activate.ps1
# Linux/macOS:
# source .venv/bin/activate

python -m pip install maturin

# Direct maturin commands bypass the custom PEP 517 backend.
# Stage the PDFium native library for this host before building:
python tools/sync_pdfium_for_wheel.py --local

# Build an optimized wheel:
maturin build --release

# Wheel output: target/wheels/
# Install the wheel matching your Python ABI and operating system/architecture:
python -m pip install path/to/your-built-wheel.whl

4. Development installation
---------------------------
# Activate your virtual environment first (see section 3).
python tools/sync_pdfium_for_wheel.py --local
maturin develop --release

# After Rust changes, rerun maturin develop --release to rebuild the extension.

5. CI and cross-platform packaging
----------------------------------
GitHub Actions builds seven wheel targets:
- Windows: x64, x86, ARM64
- Linux: x64, ARM64
- macOS: x64, ARM64

CI explicitly stages the correct native library before invoking maturin-action:
python tools/sync_pdfium_for_wheel.py --target <platform>

Examples of <platform>: win-x64, linux-arm64, macos-arm64.
The CI staging command is intentionally separate from the host-based --local
workflow; cross-compilation must not rely on host architecture detection.

Wheels use the CPython stable ABI (cp38-abi3) for Python 3.8+ where supported.
Linux release wheels are built with the configured manylinux target. Wheel
filenames vary by package version, architecture, and platform tag.

PyPI publication uploads wheels only; a source distribution (.tar.gz) is not
published. Source installation remains available through GitHub.

Notes
-----
- PDFium is loaded on demand by the PDF helpers; ordinary text conversion does
  not require importing the PDF module.
- Use the wheel appropriate for the target system. Do not copy PDFium binaries
  from a different operating system or architecture.
- For additional packaging details, see pyproject.toml, build_backend.py,
  tools/sync_pdfium_for_wheel.py, and .github/workflows/build.yml.

6. Windows 7 source installation (legacy)
-----------------------------------------
Windows 7 is a legacy environment with these tested tool limits:
- Python: 3.8.x maximum.
- maturin: 1.5.1 (latest version verified working on Windows 7).
- A compatible Rust toolchain (MSRV 1.75.0) and Windows build tools are still required.

Create a virtual environment using Python 3.8 and activate it:

# Windows PowerShell:
py -3.8 -m venv .venv
.\.venv\Scripts\Activate.ps1

# Install the Windows 7-compatible maturin version:
python -m pip install "maturin==1.5.1"

# IMPORTANT: Disable PEP 517 build isolation so pip uses maturin 1.5.1
# from the active virtual environment instead of installing a newer version.
python -m pip install --no-build-isolation "git+https://github.com/laisuk/opencc_pyo3.git@master"

The custom PEP 517 backend still stages the matching PDFium native library
for this Git source installation. No manual PDFium sync is needed.

Without --no-build-isolation, pip may install a newer maturin in its temporary
build environment. In the tested Windows 7 environment, maturin 1.15.0 failed
at the metadata stage with exit code 3221225785 (0xC0000139,
STATUS_ENTRYPOINT_NOT_FOUND).

Verified on Windows 7 x64: source wheel build and installation succeeded with
maturin 1.5.1; OpenCC s2t conversion succeeded; PDFium processed a 4,410-page
PDF with CJK paragraph reflow enabled. This is a tested local configuration,
not a guarantee that all future source revisions or toolchains support Windows 7.
